# Physics Sandbox

[![CI](https://github.com/ramsarma21/physicsSim/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/ramsarma21/physicsSim/actions/workflows/ci.yml)

A physics-true scene builder and "video generator": real-world objects (113 catalog items with true sizes, masses and materials), a validated rigid-body engine, a realistic three.js 3D view, an AI builder (describe a scene, drop a photo, or edit what's on screen), and frame-perfect MP4 export with impact sounds.

## Run locally
```bash
npm ci
npm run build:engine     # engine Web Worker bundle (web/sim/engine-worker.js)
npm run vendor:three
python3 web/server.py 8790   # then open http://localhost:8790
```
The AI builder needs a TrueFoundry key on the server side (see `ai/DESIGN.md`); everything else runs without it. `?engine=browser` runs the whole sandbox in the browser (the default on any non-localhost host).

## Development
Work on a branch (`dev`, or a feature branch), open a pull request into `main`, and merge when CI is green. CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) runs on every push to `main` and `dev` and on every pull request:

| Job | Runs |
| --- | --- |
| Checks (Linux, Node 24 and 26) | syntax of every tracked JS/TS/Python file; `vercel.json`'s function patterns against the files of the commit; `vendor:three:check`, `vendor:media:check`, `vendor:clerk:check`, `gen:scenarios:check`, and `web/sim/sprites.js` / `unicode.js` regenerated byte for byte; the engine bundle rebuilt (it must equal the committed one); every tracked `*.test.mjs`; `npm run build:static:nogen`; the engine validators `research/rw-validate*.ts` (`rw-validate.ts` is a smoke run: it has no pass/fail gate and fails only by crashing) |
| Scene builder tests (Linux) | every `machines/test_*.py` |
| Engine bundle, unit tests, deploy check, parity (macOS arm64) | every tracked `*.test.mjs` under Node 24 (Vercel's runtime) and Node 26; `npm run build:static:nogen`; `npm run check:vercel` (`vercel build` on the exact upload, then the built functions are called; nothing is deployed); `web/sim/trig.js` regenerated on macOS libm; `tools/parity/run.sh` against `web/server.py` started in the job (a step that skips part of its checks, or a server that dies, fails the job) |
| Python <-> JS parity (Linux x64, glibc) | `tools/parity/run.sh` as in the macOS job, on glibc's libm (non-blocking until it has passed on `main`) |

The engine bundle (`web/sim/engine-worker.js`, `engine-math.js`) is committed. Every job that needs it rebuilds it from the clean checkout (`npm run build:engine`: nothing outside the repository is needed, see Determinism) and fails if the result differs from the committed bundle, or if the bundle is not committed, as a Vercel deploy would; so after any change under `tooling/src/sim` or to the engine's math in `tools/`, rebuild it, run the parity tools and commit it. The engine validators run with the bundle's math (`.github/scripts/validators.sh`: `node --import ./tools/engine-math-node.mjs`), as the server's worker does. Commit what a tracked file reads or imports with it (a validator's fixture under `tools/parity/fixtures/`, a new module): CI's checkout has only what is in git. Locally:

```bash
npm run test:ai && npm run test:accounts && node --test "web/ai/test/*.test.mjs"
for t in machines/test_*.py; do python3 "$t"; done
.github/scripts/validators.sh       # the engine validators, with the bundle's math
bash tools/parity/run.sh            # with web/server.py running on :8790
npm run build:static:nogen && npm run check:vercel
```

**Deploys (Vercel).** The Vercel project is connected to this repository, and a push builds (`vercel.json` has no `ignoreCommand` any more: the one that skipped every git-triggered build while `tools/fdlibm.ts` imported the never-committed Apple-libm pow tables is gone with them, as pow is `tools/crpow.ts`): `npm run build:static` rebuilds the engine bundle and fails unless it equals the committed one. Check a deploy first with `npm run check:vercel`, as [`docs/DEPLOY.md`](docs/DEPLOY.md) describes.

## Layout
- `web/` app (view3d, models, inspector, export, AI panel, account library), `web/sim/` exact JS port of the scene builder + engine worker
- `machines/` Python scene builder and catalog (reference implementation + tests), `tooling/src/sim/` the engine (planck.js)
- `ai/` AI core (prompts, routing, benchmark), `api/` Vercel serverless functions, `tools/` build/vendor/parity tools, `docs/` deploy + accounts

## Determinism
The engine computes the same bits in every browser and on the server, on any machine: `npm run build:engine` replaces `Math.sin`, `cos`, `atan2`, `exp`, `hypot` and `pow` (and `**`) in the bundle by `tools/fdlibm.ts`'s, whose `pow` is `tools/crpow.ts` (correctly rounded, written for this project; its tables come from `node tools/gen-crpow-tables.mjs`, which `--check` verifies), and the server's worker loads the engine through `tools/engine-math-node.mjs`, which does the same in node. The Python builders take their powers, and their sin/cos at multiples of 30 degrees, from `machines/crmath.py`, which gives `web/sim`'s bits. Their other libm calls (`tan`, `atan2`, `acos`, `asin`, `sinh`/`cosh`/`asinh`, `log10`, sin/cos at other angles) are still the platform's in Python and V8's in `web/sim`: they can differ in the last bit, which shows in a document only where a printed number lands exactly on a rounding tie (the one known case is a hanging chain placed at an odd multiple of 1/64 m: `tools/parity/mechanisms.mjs --groups chainties`). `node tools/test-crpow.mjs` checks `pow` against MPFR and for the same bits in node, bun, deno and Chromium.
