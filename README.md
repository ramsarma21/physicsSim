# Physics Sandbox

[![CI](https://github.com/ramsarma21/physicsSim/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/ramsarma21/physicsSim/actions/workflows/ci.yml)

A physics-true scene builder and "video generator": real-world objects (113 catalog items with true sizes, masses and materials), a validated rigid-body engine, a realistic three.js 3D view, an AI builder (describe a scene, drop a photo, or edit what's on screen), and frame-perfect MP4 export with impact sounds.

## Run locally
```bash
npm ci
npm run build:engine     # engine Web Worker bundle (web/sim/engine-worker.js)
npm run vendor:three
python3 web/server.py 8790   # then open http://localhost:8790
```
The AI builder needs a TrueFoundry key on the server side (see `ai/DESIGN.md`); everything else runs without it. `?engine=browser` runs the whole sandbox in the browser (the default on any non-localhost host).

## Development
Work on a branch (`dev`, or a feature branch), open a pull request into `main`, and merge when CI is green. CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) runs on every push to `main` and `dev` and on every pull request:

| Job | Runs |
| --- | --- |
| Checks (Linux, Node 24 and 26) | syntax of every tracked JS/TS/Python file; `vercel.json`'s function patterns against the files of the commit; `vendor:three:check`, `vendor:media:check`, `vendor:clerk:check`, `gen:scenarios:check`, and `web/sim/sprites.js` / `unicode.js` regenerated byte for byte; the `node --test` files that do not load `web/sim`; the engine validators `research/rw-validate*.ts` (`rw-validate.ts` is a smoke run: it has no pass/fail gate and fails only by crashing) |
| Scene builder tests (Linux) | every `machines/test_*.py` |
| Engine bundle, unit tests, deploy check, parity (macOS arm64) | every tracked `*.test.mjs` under Node 24 (Vercel's runtime) and Node 26; `npm run build:static:nogen`; `npm run check:vercel` (`vercel build` on the exact upload, then the built functions are called; nothing is deployed); `web/sim/trig.js` regenerated on macOS libm; `tools/parity/run.sh` against `web/server.py` started in the job (a step that skips part of its checks, or a server that dies, fails the job) |

Until the open-source `pow` lands (see Status), the real engine bundle cannot be built from this repository, so CI tries `npm run build:engine` and: on Linux skips the steps that load `web/sim` with a notice; on macOS builds the bundle with `pow = Math.pow` instead ([`.github/scripts/stub-pow.sh`](.github/scripts/stub-pow.sh)), which on macOS gives the same bits as the Apple tables, so everything above runs there (the real tables themselves are not tested in CI, and the stub bundle is never deployed). Both switch to the real bundle by themselves from the first commit where `npm run build:engine` works from a clean checkout. Locally, with the bundle built:

```bash
npm run test:ai && npm run test:accounts && node --test "web/ai/test/*.test.mjs"
for t in machines/test_*.py; do python3 "$t"; done
bash tools/parity/run.sh            # with web/server.py running on :8790
npm run build:static:nogen && npm run check:vercel
```

**Deploys (Vercel).** The Vercel project is connected to this repository, but a build from git cannot make the real engine bundle yet, so `vercel.json`'s `ignoreCommand` skips (cancels) every git-triggered build while `tools/apple-pow-tables.ts` is missing and `tools/fdlibm.ts` still imports it; it stops skipping by itself once the open-source `pow` is in. Until then deployments are made from the development machine, after `npm run check:vercel`, as [`docs/DEPLOY.md`](docs/DEPLOY.md) describes.

## Layout
- `web/` app (view3d, models, inspector, export, AI panel, account library), `web/sim/` exact JS port of the scene builder + engine worker
- `machines/` Python scene builder and catalog (reference implementation + tests), `tooling/src/sim/` the engine (planck.js)
- `ai/` AI core (prompts, routing, benchmark), `api/` Vercel serverless functions, `tools/` build/vendor/parity tools, `docs/` deploy + accounts

## Status
The deterministic `pow` used by the engine bundle is being replaced by an open-source correctly-rounded implementation; until then `npm run build:engine` needs `tools/apple-pow-tables.ts`, which is not in this repository.
